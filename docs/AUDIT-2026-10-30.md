# Audit 2026-10-30

This audit used the app the way a new user would. It ran the production build (`bun run build` and `bun run start`) against a disposable database and a fixture library. The fixture library held JPEG, PNG and WebP images, a valid and a truncated MP4, an MP3, a PDF, Markdown and text notes, valid and broken JSON, an OBJ model, a corrupt JPEG, and 40 extra subfolders. The personal `db.sqlite` was not opened.

Screenshots were taken at 1440×900. Each finding below states its severity, what happened, the root cause, and whether this pass fixed it.

## Findings, ranked

### P0: broken for every new library

1. **Favorites never worked on a new library.** Adding a favorite returned HTTP 500 ("No hay un perfil activo"). `ensureDefaultProfile()` uses the server database but was only called from the browser (`settings-context.tsx`), where it cannot work. It also inserted the color `var(--dt-primary-500)`, which the `Profile_color_format_check` constraint rejects. **Fixed:** the server creates or activates the default profile at startup with a hex color, and the browser call is gone.
2. **The Favorites page was always blank.** `FavoritesView` returned `null` unless it received `isVisible`, and the router never passes it. **Fixed:** the default is now visible.
3. **The Albums and Collections pages looped forever on an empty library.** They sent about 30 requests per second and showed "Loading..." indefinitely. The views reloaded whenever the store was empty, and an empty library stays empty after loading. **Fixed:** each view loads once.
4. **New albums and collections did not appear until reload.** The views read Zustand stores, but creation used React Query mutations that never updated those stores. The infinite loop above had hidden this. **Fixed:** the views reload their store after each mutation.
5. **Video thumbnails were blank for every clip shorter than 5 seconds, valid files included.** Ingestion seeks to 5 s, so FFmpeg wrote an empty file. The fallback then stored an SVG placeholder, and the routes served it as `image/webp` or `image/jpeg` because the `Video` table has no MIME column. **Fixed:** FFmpeg retries from the first frame when the seek passes the end. The video thumbnail MIME type is now detected from the stored bytes. The FFmpeg GIF fallback is accepted instead of discarded. The file name inside the SVG placeholder is escaped.
6. **The production server bundle ran in development mode.** `bun build` replaced `process.env.NODE_ENV` with `"development"` at build time. As a result, the production and desktop builds sent internal error details to the client, exposed the dev-only `/api/system/dbinfo` route, and skipped the rate limiter. **Fixed:** `build:server` now defines `NODE_ENV` as `production`. The rate limiter now counts only mutations, so a thumbnail grid cannot reach its limit of 1,000 requests per 15 minutes.

### P1: core flows that were missing or fragile

7. **Moving files had no menu entry.** **Fixed:** the context menu now has a **Move to…** entry. The dialog lets you filter by folder name, searching up to 200 folders instead of the first 100. It hides the folder the files already live in. After a move, a toast offers **Undo**, which moves each file back to its source folder with the same authorized API. If the selection includes folders, the dialog skips them and says so. Before, that case failed silently.
8. **Reindexing showed 0% until it finished and could not be stopped.** **Fixed:** the server emits progress after each folder ("Indexed 12 of 48 folders"). The terminal now has a **Stop** button, backed by `POST /api/folders/:id/reindex/cancel`. The run stops after the folder that is syncing. Each folder commits on its own, and a stopped run does not mark unvisited folders as missing. In the test, a run stopped at 22 of 48 folders, and the next run finished the remaining files.
9. **The context menu and its "Add to…" submenu overflowed the viewport.** Near the bottom of the screen, **Favorites** was cut off and covered by the floating "Open file browser" button. **Fixed:** both menus now stay inside the viewport and flip when needed.
10. **The folder search sent nothing to the server.** `findFolders()` dropped `search`, `sortBy`, `sortOrder` and `offset`, so the Settings folder search and the move dialog filter did nothing. **Fixed:** these filters are now sent to the server.
11. **Album and collection cards requested routes that do not exist** (`/recent-media`, `/media`) and always showed "No images". **Fixed:** the cards now use `/:id/images`.
12. **A corrupt image showed as a blank tile.** **Fixed in the UI:** a tile that fails to load now shows the file-type icon. _Open:_ the server still answers `500` for that thumbnail; `422` would be more accurate.
13. **Every document showed a "PDF" badge,** Markdown and text notes included. **Fixed:** the badge now follows the MIME type (PDF, MD, TXT, DOC).
14. **`dev:full` left Vite running when the frontend missed its 120 s start deadline on Windows.** The orphaned process kept the port busy, so the next start failed. **Fixed:** `dev-vite-headers.js` now stops the whole process tree with `taskkill /T`. It also stopped printing "isolated standalone session" when it runs under `dev:full`. _Open:_ on a loaded machine, a cold Vite start can still miss the 120 s deadline.
15. **`bun run test` exited 1 after all tests passed.** The cleanup helper returned failure without a message. **Partly fixed:** each silent branch now logs its cause. The underlying failure did not reproduce in the final run; see the closeout report.

### P2: open debt found by this audit

16. **`dev:full` on a new database starts with no schema.** Only production applies migrations. The dev server reports ready, every request fails, and production then refuses that file. Recommended fix: make the dev server fail fast with the `db:migrate` command, or apply the same migrations.
17. **Adding a folder does not start indexing.** A new user sees "0 images" until they find the per-folder reindex button. The empty dashboard also gives no first-run guidance.
18. **Several counters go stale.** Sidebar Favorites showed 0 with one favorite. An album card showed "Images: 0" after an image was added. The Settings folder list counts only direct children.
19. **Full-text search is not fed by the canonical indexer.** `files_fts` indexes the legacy `File` table, which is empty. Global search falls back to `LIKE`, which will slow down on a large library. Search does not match file contents, such as a prompt inside a JSON file.
20. **Each video tile requests 8 to 9 thumbnails on load** for its preview animation. On a large library this multiplies FFmpeg work.
21. **Backups have no UI.** `db:backup`, `db:backup:verify` and `db:restore` work from the CLI. They ran against the disposable database while the server was running. The restore wrote a new file and did not overwrite.
22. **Videos ingested before this fix keep their stored placeholder.** Reindexing does not regenerate thumbnails for existing assets; `bun run db:generate-video-thumbnails` is the existing tool for that.
23. **`test:e2e` starts `dev:full` with `.env`,** so it points at `db.sqlite`. Use `bun scripts/run-production-smoke.ts`, which creates a disposable database, until the dev E2E config isolates its database.
24. **Lint debt is mostly React Compiler rules** (53 `set-state-in-effect`, 18 `refs`, 12 `preserve-manual-memoization`). These need behavior review, not mechanical edits. This pass fixed only the six redundant `alt` attributes.
25. **Some UI strings are still Spanish** ("Se encontraron…", "Agregado correctamente", "Perfil por defecto"), although the contributor rule says English.
